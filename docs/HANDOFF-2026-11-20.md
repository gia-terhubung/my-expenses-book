Date: 2026-11-20. Written by Claude Code for the next agent (Antigravity / Gemini). Read this file first, then the spec and plan below.

## 1. Project in one paragraph

My Expenses Book is a privacy-first, offline receipt scanner (Expo SDK 58, React Native, expo-router, Drizzle ORM on SQLCipher via expo-sqlite, MMKV prefs, i18next with en / id / es / pt-BR). Monorepo: `apps/mobile` (the app), `apps/web` (Next.js landing site on Vercel, deploys only when `apps/web` changes), `docs/`. The owner works alone and pushes directly to `main` on GitHub (`gia-terhubung`). No cloud, no accounts, no analytics, no push tokens: never add a network call.

Features, all in `apps/mobile`:

1. **Month starts on payday:** pref `monthStartDay` (1–28). Home and Stats use pay periods; search and export stay on calendar months. Code: `src/stats/payPeriod.ts`, `src/dates/civil.ts`, `src/components/DayGrid.tsx`, `src/settings/MonthStartPicker.tsx`.
2. **Database copy before upgrades:** `src/db/safeMigrate.ts` (+ `expoDbFiles.ts`, wired in `src/db/DatabaseProvider.tsx`). It copies `meb.db` to `meb.db.pre-upgrade` before pending migrations, and restores via `.restoring` then an atomic move if a migration fails.
3. **Recurring expenses:**
   - Data: table `recurring_rules` (migration `0004_recurring.sql`); `receipts.recurring_rule_id` and `recurring_date`, with a partial unique index that stops duplicate occurrences.
   - Date logic: `src/recurring/occurrences.ts`.
   - Rules and catch-up: `rules.ts`, `catchUp.ts` (creates due expenses on unlock and foreground; Undo removes only untouched rows).
   - Hooks and notifications: `useRecurringCatchUp.ts`, `notify.ts`, `deviceScheduler.ts`, `useNotificationTap.ts` (local notifications only, 09:00, merchant name only, Android channel "recurring").
   - Screens: `RuleForm.tsx`, `RecurringList.tsx`, `CatchUpBanner.tsx`, routes `src/app/recurring/`. "Repeat this…" on receipt detail.
   - Backup: rules carried in backup replace and merge (`src/backup/snapshot.ts`, `applySnapshot.ts`).
4. **Dev clock**, dev builds only: deep link `myexpensesbook://dev/clock?now=<iso>&tz=<IANA>` overrides `now()` in `src/dates/clock.ts`.
5. **End-to-end scripts:** `apps/mobile/e2e/` (bash + AXe for iOS simulators). See `e2e/README.md`. Wiping app data requires `E2E_ALLOW_WIPE=1`; scripts back up to `~/MEB-e2e-backups/<UDID>/<timestamp>/` first; `restore_app_data` puts the data back.

Owner decisions worth knowing:
- Recurring rules have an "Add automatically" switch: on means the expense is saved, off means it lands as a draft.
- Notifications are sent only for draft-type rules.
- Nothing is backfilled: "Repeat this…" uses the source receipt as the first entry, and a past start date or a resumed rule starts at the next due date.
- The liability cap stays at IDR 100,000.
- Android Google ML Kit is kept and disclosed.

## 6. Known limits accepted for 1.0 (don't "fix" without asking the owner)

- No catch-up cap: missed occurrences are all created, and Undo is offered instead.
- A rule form opened on a compact screen stays full width after unfolding; typed values survive.
- "Recurring" label shows only in the review header, because there's no drafts list.
- FX is also computed for draft occurrences; the review form recomputes it on confirm.
- No foreground notification handler: catch-up covers the next foreground.
- Merge guard is order-dependent in a rare case; it never duplicates and never throws.
- FX back-fill bumps `version`, so Undo keeps those rows. This fails safe.
