# UI polish pass: tokens, Button, Card, elevation

Date: 2026-11-16. Status: proposal, awaiting owner approval. Scope: `apps/mobile/src` only.

Rule for this pass: nothing is reordered, repositioned or re-worded. Changes are limited to tokens,
two shared components, press/disabled states, shadows, and text-fitting fixes. The few places where a
fix changes a size by some dp are listed in section 6 and called out as decisions in section 7.

Evidence: screenshots in the session scratchpad `audit/` folder (Redmi 14C, 360dp wide, 2x, light
scheme, Indonesian). No dark-scheme or iOS screenshots exist, so every dark/iOS statement below is
derived from the code and tokens and must be checked on device.

## 1. Findings (most impactful first)

1. **Cards have no edge (07-folders, 08/09-settings, 12-categories, 13-tipjar).** Cards are `surface`
   (#FFFFFF) on `background` (#F7F7F5), a contrast of 1.07:1, with no border and no shadow. They read
   as faint blobs; the settings list looks like one washed-out column. Bordered controls (OptionRow,
   inputs, outline buttons) are crisp by comparison, so the app has two unrelated surface styles.
2. **No press feedback on most controls.** Of 58 `<Pressable>`, only 11 react to `pressed`, and they
   use four different effects (opacity 0.85, opacity 0.6, `border` colour as fill, none). Settings
   rows, OptionRow, every text link, the Backup/Export/Save buttons and the tabs give no feedback.
3. **Totals wrap mid-number (01-feed, 15-collection-landscape).** "Rp 12.053.89 / 9" and
   "Rp 198.238.8 / 41": `type.headline` (28sp bold) in a 156dp cell, no line limit.
4. **Buttons are hand-copied with drift.** Disabled opacity is 0.4 in forms and 0.5 in
   Backup/Export/TipJar (11-backup: the disabled primary looks like a different colour, not a state).
   Outline buttons are `surface`-filled in 02-detail but transparent in 04-review ("Buang") and
   11-backup. Outline label colour is `primary` in 02-detail and `text` in 11-backup ("Pulihkan dari
   cadangan"), where it is indistinguishable from an unselected OptionRow (10-export). Onboarding
   buttons use `radius.pill`; all others `radius.md`. Minimum height is 44 in DuplicateBanner.
5. **Draft banner bleeds off-screen (01-feed, 15).** "Lanjutkan memeriksa" has rounded corners and a
   1dp warning border but no horizontal margin, so the border runs into both screen edges.
6. **Native `<Button>` in product screens** (`capture.tsx`, `ErrorPanel`, `DbErrorScreen`): renders
   the platform default (Android: uppercase filled, default blue where no `color` is passed).
7. **Backup inputs are unfilled (11-backup).** They have no `backgroundColor`, so they show
   `background` grey; every other input (04-review, 06-search) is `surface` white.
8. **FAB (01-feed).** The only shadow in the app, written with legacy `elevation` + `shadow*` and
   literal sizes; black shadow at 0.2 will be invisible on the dark background.
9. **Touch targets under 48dp.** Tab bar items are 40dp tall (12 + 16 + 12; 01-feed), category chips
   44dp (04-review), DuplicateBanner buttons 44dp.
10. **Bottom sheet has no separation (03-add-sheet)** beyond the scrim; in dark the `surface` sheet on
    a dimmed dark screen will have almost none.
11. Noted, not fixed here because fixing moves content: screen edge padding is 16dp on feed, folders,
    categories and review but 24dp on detail, settings, export, backup and tip jar; card stack gaps are
    8dp (07, 12), 12dp (08) and 16dp (13); section headings use `headline` 28sp and outrank the screen
    title `title` 20sp (10-export: "Ekspor" is smaller than "Rentang tanggal"); back affordances come in
    three styles (native arrow, "Kembali", "‹ Kembali"). See section 7.

## 2. Token changes (`src/theme/tokens.ts`)

Spacing, radius and existing colours are **unchanged**. `radius` already covers every case; the FAB
moves from a literal 30 to `radius.pill`.

### 2.1 New colours (state fills)

| Token | Light | Dark | Use |
|---|---|---|---|
| `surfacePressed` | `#EEEEEA` | `#26272A` | pressed fill for cards, outline buttons, OptionRow, chips, feed rows |

Add these five rows to `PAIRS` in `contrast.test.ts` at 4.5. Existing pairs are untouched.

### 2.2 Elevation (new, per scheme)

```ts
export const lightElevation = {
  none: "none",
  card: "0 1px 2px rgba(28,28,30,0.08), 0 0 0 1px rgba(28,28,30,0.05)",
  raised: "0 4px 12px rgba(28,28,30,0.16), 0 1px 3px rgba(28,28,30,0.10)",
  overlay: "0 -4px 24px rgba(28,28,30,0.16)",
} as const;
export type ElevationTokens = { [K in keyof typeof lightElevation]: string };
export const darkElevation: ElevationTokens = {
  none: "none",
  card: "0 0 0 1px #2E2F32",
  raised: "0 4px 12px rgba(0,0,0,0.5), 0 0 0 1px rgba(255,255,255,0.08)",
  overlay: "0 -4px 24px rgba(0,0,0,0.6), 0 0 0 1px #2E2F32",
};
```

`Theme` gains `elevation: ElevationTokens`; `tokens.light/dark` wire the matching object. Usage:
`style={{ boxShadow: theme.elevation.card }}`.

- **Why `boxShadow`:** the app is New Architecture only, and the installed RN 0.88.1 ships
  `processBoxShadow`. One string works on both platforms, supports several layers and spread, and
  draws outside the box without affecting layout. iOS `shadow*` does nothing on Android; Android
  `elevation` cannot set colour, offset or blur and changes z-order. Keeping two parallel definitions
  is the drift this pass removes.
- **Why a 1px spread ring:** it gives cards the edge they lack without a `borderWidth`, which would
  shrink content by 1dp. In dark, drop shadows cannot show on #101112, so `card` is the ring alone in
  the `border` colour.
- **Three levels only:** `card` for resting surfaces, `raised` for the FAB, `overlay` for the bottom
  sheet (shadow thrown upward). Buttons stay flat.
- Per RN documentation, outset `boxShadow` needs Android 9 (API 28); `minSdkVersion` is 26, so API
  26-27 devices render no shadow and look as they do today. Acceptable; not verified on such a device.

### 2.3 Type and state constants

```ts
// type: add
label: { fontSize: 16, lineHeight: 22, fontWeight: "600" },
// new export, added to Theme as `state`
export const state = { disabledOpacity: 0.4, pressedOpacity: 0.6 } as const;
// new export, added to Theme as `size`
export const size = { touch: 48, row: 56, fab: 60 } as const;
```

- `label` equals the `body` + `fontWeight: "600"` pair written inline at most button and link sites; no visual change.
- `disabledOpacity: 0.4` replaces the 0.4/0.5 mix. `pressedOpacity: 0.6` is for text-only buttons.
- `size` names the three recurring minimum heights; they are always `minHeight`, never `height`
  (except the square FAB), so large font scales grow the control.

## 3. Components

### 3.1 `src/components/Button.tsx`

```ts
export type ButtonProps = {
  label: string;
  onPress: () => void;
  variant?: "primary" | "secondary" | "quiet";   // default "secondary"
  tone?: "default" | "danger" | "muted";         // default "default"; "muted" is for quiet only
  align?: "center" | "start";                    // default: "start" for quiet, else "center"
  detail?: string;                               // second line, type.caption (Backup merge/replace)
  disabled?: boolean;
  busy?: boolean;                                // implies non-interactive
  busyIndicator?: boolean;                       // default true; false keeps the label visible
  accessibilityLabel?: string;                   // default: label
  accessibilityHint?: string;
  testID?: string;
  style?: StyleProp<ViewStyle>;                  // layout only (flex, margin, alignSelf, padding); merged last
};
```

There is one size. A smaller size would break the 48dp rule and no screen needs a larger one.
"Destructive" is `tone="danger"` on `secondary` or `quiet`; a solid red button would need an
`onDanger` colour and nothing in the app uses one today.

Container (a single `<Pressable accessibilityRole="button" ...>`; the literal attribute keeps
`pressableGuard` green):

| | primary | secondary | quiet |
|---|---|---|---|
| `backgroundColor` | `primary`; pressed `primaryPressed` | `surface`; pressed `surfacePressed` | transparent |
| border | none | 1dp `border` | none |
| label colour | `onPrimary` | `primary`; danger: `danger` | `primary`; danger: `danger`; muted: `textMuted` |
| pressed, other | none | none | `opacity: state.pressedOpacity` |
| `paddingHorizontal` | `spacing.lg` | `spacing.lg` | 0 |

Shared: `minHeight: size.touch`, `minWidth: size.touch`, `paddingVertical: spacing.sm`,
`justifyContent: "center"`, `alignItems` from `align`, `borderRadius: radius.md`,
`borderCurve: "continuous"`, `opacity: disabled ? state.disabledOpacity : 1` (busy does not dim).
Label: `type.label`, `textAlign` from `align`, no `numberOfLines` (labels wrap and the button grows).
`detail`: `type.caption`, `onPrimary` on primary, else `textMuted`.

States: `disabled={disabled || busy}`,
`accessibilityState={{ disabled: !!disabled || !!busy, busy: !!busy }}`. When `busy` and
`busyIndicator`, render `<ActivityIndicator color={labelColour} />` absolutely centred and give the
label `opacity: 0`, so the button keeps its width and height. The accessible name stays the label.

Decided here, flagged in section 7: secondary labels are `primary` everywhere (today four sites use
`text`), and secondary is always `surface`-filled.

### 3.2 `src/components/Card.tsx`

```ts
export type CardProps = {
  children: React.ReactNode;
  onPress?: () => void;                  // present: Pressable with accessibilityRole="button"
  disabled?: boolean;
  elevation?: "card" | "none";           // default "card"
  tone?: "surface" | "background";       // default "surface"
  accessibilityLabel?: string;
  accessible?: boolean;                  // static cards that read as one element (InfoRow)
  testID?: string;
  style?: StyleProp<ViewStyle>;          // layout only; merged last
};
```

Style: `minHeight: size.row`, `flexDirection: "row"`, `alignItems: "center"`, `gap: spacing.md`,
`paddingHorizontal: spacing.lg`, `paddingVertical: spacing.sm`, `borderRadius: radius.md`,
`borderCurve: "continuous"`, `backgroundColor: colors[tone]`, `boxShadow: theme.elevation[elevation]`.
Pressed (only with `onPress`): `backgroundColor: surfacePressed`. Disabled: `state.disabledOpacity`.
Without `onPress` it renders a `View`. Content stays `children`; no label/value props.

`paddingVertical: spacing.sm` is new for settings rows and tip rows but does not change their height:
one `body` line (22) + 16 is below the 56 minimum at font scale 1, and at large scales the padding is
what stops text touching the edge.

### 3.3 OptionRow alignment

OptionRow is a bordered control, like a secondary Button, so it keeps its border and gets no shadow.
Changes: style becomes a function of `pressed` (`surfacePressed` unselected, `primaryPressed`
selected), `borderCurve: "continuous"`, label uses `type.label`, and a new
`role?: "radio" | "checkbox"` prop (default `"radio"`, passed as `accessibilityRole={role}`) so
FilterSheet's category rows stop duplicating it. Dimensions are unchanged.

### 3.4 Guard changes

- `pressableGuard.test.ts`: the pass removes about 40 `<Pressable>` tags; 18 remain (16 listed in
  section 4.5 plus Button and Card). `expect(seen).toBeGreaterThan(40)` must become
  `toBeGreaterThan(15)`. This is a required edit, not optional: the test fails otherwise.
- Add to the same file: no non-test file outside `src/dev/` imports `Button` from `"react-native"`.
- New `Button.test.tsx` / `Card.test.tsx`: role, label fallback, disabled and busy states, `onPress`
  not fired when disabled or busy.

## 5. Defect fixes

5.1 **Totals wrap** (`receipts/TotalsHeader.tsx:41-46`). Render the money and the "not converted"
note as two `Text` nodes instead of one `totalLine()` string (same words, same order):

```tsx
<Text numberOfLines={1} style={[theme.type.body, { color: theme.colors.textMuted }]}>{label}</Text>
<Text numberOfLines={1} adjustsFontSizeToFit minimumFontScale={0.6}
      style={[theme.type.headline, { color: theme.colors.text }]}>
  {formatMoney(tot.homeMinor, home, locale)}
</Text>
{tot.unconverted > 0 ? (
  <Text style={[theme.type.caption, { color: theme.colors.textMuted }]}>{notConverted(tot.unconverted)}</Text>
) : null}
```

Estimated from the screenshot: "Rp 198.238.841" needs about 172dp at 28sp and the cell is 156dp, so
it lands near 25sp; a 13-digit amount lands near 22sp. The floor is 16.8sp. The accessible label should keep the combined
`totalLine()` string (`accessible` + `accessibilityLabel` on the cell View). The header becomes one
line shorter, which is the fix itself. `totalLine` stays for other callers.

5.2 **Draft banner bleed** (`app/(tabs)/index.tsx:70`). Add `marginHorizontal: spacing.sm` and change
`paddingHorizontal` from `spacing.lg` to `spacing.sm`. The label stays at 17dp from the screen edge;
only the border moves in by 8dp.

5.3 **Backup inputs** (`backup/BackupScreen.tsx:467`). Add `backgroundColor: theme.colors.surface`.

5.4 **FAB** (`app/(tabs)/index.tsx:95, 113-126`). Remove `elevation` and the four `shadow*` props; add
`boxShadow: theme.elevation.raised`; `width/height: size.fab`, `borderRadius: radius.pill`; pressed
becomes `backgroundColor: primaryPressed` instead of opacity 0.85. Same position and size.

5.5 **Tab bar target** (`layout/BottomTabBar.tsx`, `styles.item`). Add `minHeight: size.touch` and
`justifyContent: "center"` to `styles.item`. The bar grows 8dp. A `hitSlop` alternative is not
reliable here because the extra area would lie outside the bar's own bounds.

5.6 **Bottom sheet** (`capture/CaptureSheet.tsx`, the sheet `View` after line 99). Add
`boxShadow: theme.elevation.overlay`.

5.7 **Disabled look** (11-backup, Export, TipJar). Covered by Button/Card: 0.5 becomes 0.4.

Sizes that change (everything else is paint only):

| Change | Delta |
|---|---|

| Tab bar (5.5) | 8dp taller |

Re-check on device, light and dark, Android and iOS:

- `boxShadow`: the multi-layer and spread syntax renders on both platforms; shadows are not clipped by
  `ScrollView` edges (cards sit 16-24dp from the edge, blur is at most 12); nothing regresses in
  scroll performance on the settings and categories lists; the dark ring is visible but not harsh.
- Feed totals: `adjustsFontSizeToFit` on Android with a 9-digit and a 13-digit total, a
  "not converted" note, font scale 1.3 and 2.0, and the landscape list pane. The two totals may settle
  at different sizes side by side; if that looks wrong, the follow-up is a shared measured scale.
- Font scale 2.0: buttons with `detail` (Backup merge/replace), Card rows with long values (settings
  "Bahasa"), two-button rows (02-detail, review footer).
- Busy state: Save on review keeps its width with the spinner; Export and Backup keep their text.
- Pressed colours in dark, selected OptionRow pressed, FAB pressed.
- TalkBack/VoiceOver: Card rows still read as one element with the same label; busy and disabled are
  announced.
- Tests: `contrast.test.ts` with five new pairs, `pressableGuard.test.ts` with the new threshold, and
  existing screen tests that query by role/label (labels are unchanged, so they should pass).

## 7. Open decisions for the owner

1. **Secondary button label colour.** Spec picks `primary` (green) everywhere so outline buttons do
   not look like OptionRows. This recolours four labels that are `text` today (Backup restore,
   capture "keep one", review Cancel-while-editing, DuplicateBanner). Alternative: `text` everywhere.
2. **Tab bar 48dp target** (5.5) grows the bar by 8dp. It is an accessibility requirement of the
   product spec, but it is a geometry change; say no and it stays at 40dp.
3. **Not included, needs a yes to add:** unify screen edge padding (16 vs 24), unify card stack gaps
   (8/12/16), demote section headings from `headline` to `title` so screen titles outrank them, unify
   the three back affordances. Each one moves content.
4. **Pressed feedback on Android:** spec uses colour fills on both platforms rather than
   `android_ripple`, for one behaviour to test. Ripple is the more native choice if preferred.
