# M3 Organize Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn saved receipts into an organized, searchable book. It has five parts:
- a month-grouped feed with home-currency totals
- receipt detail and edit
- folders and tax-year views
- category management
- FTS5 search with filters

All of it gets a two-pane list–detail layout on medium and expanded windows.

**Architecture:**
- **Data:** one filter-driven query module (`receiptQueries.ts`) serves the feed, folders, tax years and search. Paging is keyset. Totals come from SQL aggregates that never mix currencies.
- **Refresh:** a tiny in-process change emitter tells mounted lists to refetch after any write.
- **Screens:** they share `ReceiptList`, `ReceiptDetail` and `ReceiptListDetail`. `ReceiptListDetail` is the two-pane wrapper, and it keeps the selected receipt in a route param so fold/unfold keeps the selection.
- **Edit:** reuses the M2 review form in a new `edit` mode.

**Tech Stack:**
- Expo SDK 58 and RN 0.88, TS strict, Expo Router (routes in `src/app`).
- expo-sqlite SQLCipher with Drizzle and FTS5.
- i18next with 4 locales.
- `@expo/ui` ~58.0.27 (already a dependency) for the native date picker.
- Jest with jest-expo.

**Spec:** `docs/superpowers/specs/2026-11-04-my-expenses-book-design.md` (M3 row, "Adaptive layout", "Folders", "Categories", "Tax year", "Currency"/"FX rate"). Carry-overs: `docs/m2-followups.md` § "Carry into M3".

## Global Constraints

**Testing and tooling**
- Tests NEVER live under `src/app/`, because Expo Router bundles them as routes. Route files stay thin, and all logic and tests go in `src/<feature>/`.
- All commands run in `apps/mobile`. Gates: `npx jest`, `npx tsc --noEmit` and `npm run check:pii` must all pass at every commit.
- Git identity is the repo-local Gia <terhubungapp@gmail.com>. Never use the work identity. Never commit, read or quote `apps/mobile/spikes/receipts/` or `spikes/ocr-dumps/` (real PII). All test data is synthetic.
- No new npm dependencies.

**Money and totals**
- Money is integer minor units. Display goes through `formatMoney(minor, code, locale)` from `src/money/money.ts`. Never use floats.
- "Totals never mix currencies." A home-currency total sums only rows with `home_currency_at_save = <current home>` AND `amount_home_minor IS NOT NULL`. Other rows are counted as `unconverted` and shown as "N not converted", never added in.

**What appears where**
- Feed, folders, tax years, search and totals show `status = 'confirmed'` AND `deleted_at IS NULL` only. Drafts stay reachable through the existing "Continue reviewing (N)" banner.
- "Sorting/grouping uses `purchased_at`": order by `purchased_at_local DESC, id DESC`. Group months by `purchased_at_local.slice(0, 7)`, which is wall-clock time, so a receipt shot in Paris stays in its Paris month.

**Data model**
- Soft delete only. Every write bumps `updated_at` and `version`, as the existing repository functions do.
- FTS warning (`src/db/schema.ts`): no migration may rebuild `receipts`. M3 adds only `CREATE INDEX`.

**Layout and platform**
- Layout branches only on `useWindowClass()`: compact <600dp, medium 600–839dp, expanded ≥840dp. Never branch on device model. No orientation lock.
- Fold/unfold, rotation and window resize must not lose the selected receipt, the scroll position, the search text, the filters or in-progress edit text. Keep state in route params or in hooks above any `TwoPane` split.

**UI rules**
- Every RN `Modal` is `AppModal` from `src/components/AppModal.tsx` (enforced by `appModalGuard.test.ts`).
- Touch targets ≥44pt; the codebase uses `minHeight: 48`. Colors, spacing and type come from `useTheme()`. Text scales with the system font size.
- Every new UI string goes into all 4 locale files `src/i18n/locales/{en,id,es,pt-BR}.json` with the exact same key set (`locales.test.ts`). en is authored; id, es and pt-BR are careful translations.

**Network**
- Network: only the existing FX host. M3 adds no network calls.

## Review Focus

1. **Mixed currencies in a total** (offline, home currency just changed, or a foreign receipt with no rate yet): the total must show only the converted sum plus "N not converted". It must never add raw foreign minor units. Pinned in Task 1 (`sumHome` excludes, counts unconverted) and Task 3 (header renders the "not converted" note).
2. **Fold/unfold or rotation with a receipt selected, or mid-edit:** the same receipt stays selected. On compact the detail shows with a working back control, and typed edit text survives. Pinned in Task 4 (`ReceiptListDetail` re-render across window classes) and Task 5 (edit values survive a `TwoPane` class change).
3. **Search text that is only punctuation, quotes, FTS operators (`AND`, `"`, `*`, `-`), diacritics (`café` vs `cafe`) or an Indonesian word prefix (`indom` → Indomaret)**: never throws. Searching combined with filters returns the intersection. Pinned in Task 1.
4. **Deleting a folder or category that still holds receipts:** the receipts never disappear from the feed or the totals. A deleted folder's receipts go to "No folder". A deleted custom category's receipts move to `default:other`. Pinned in Task 7 and Task 8.
5. **Tax year that starts in a month other than January, with receipts on the boundary days** (start April: `2026-03-31` vs `2026-04-01`; a receipt whose local wall-clock date differs from its UTC date): the receipt's local date decides the tax year. Pinned in Task 2 and Task 1 (range filter on `purchased_at_local`).

## Rulings made while planning

- **Drafts:** drafts are excluded from feed, search and totals. They stay reachable only through the drafts banner. Cost if wrong: one filter to relax.
- **Folder default currency:** `folders.default_currency` gets no UI in M3. Nothing consumes it yet; capture-into-folder is not in scope. Cost: one field added later.
- **Duplicate check:** it runs only at review time, not when editing a confirmed receipt. Cost: a user could edit a receipt into a duplicate silently.
- **Category delete:** a custom category's receipts move to `default:other`, not to uncategorized, so every receipt keeps a category. Defaults can be renamed or reset, never deleted.
- **Sort order:** sorting uses `purchased_at_local` (wall-clock), which matches the month grouping, rather than `purchased_at_utc`. Cost: receipts from different time zones on the same day may interleave by local clock.
- **Refresh:** list refresh uses an in-process change emitter, not Drizzle `useLiveQuery`. That keeps the sync DB wrapper and the test DB unchanged.
